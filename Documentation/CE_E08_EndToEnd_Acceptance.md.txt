## 1. The v0.2 UX baseline — scope statement

The CHIA County Explorer v0.2 UX baseline delivers the **geography-first
journey** (§3.1), implemented across CE-E01–CE-E07:

```
U.S. map  →  State (map or accessible selector)  →  County (map or accessible selector)
          →  Visual County Profile (breadcrumb, identity, four-dimension snapshot,
             CE-E05 indicators, "What Stands Out?" interpretation)
          →  Dimension  →  "Investigate" drill-down:
                Underlying Data  →  Evidence  →  Methodology (scoped + page-level)
                                              →  Provenance (scoped + page-level)
```

with geographic context continuously visible (state heading + "United
States" link; county breadcrumb `United States → {State} → {County}` with
`aria-current="page"`) and announced to assistive technology on every
client-side transition (CE-E07 route announcer).

### Explicitly NOT part of the v0.2 §14 baseline

The specification's §3 also describes the following, for which §14 allocated
**no implementation slice** and which CE-E02–CE-E07 did not build. They are
**out of scope for the v0.2 UX baseline** and are candidate v0.3 roadmap
items (they depend on the §7 analytical-map / measure-selector capability,
which is likewise unbuilt — see CE-E07's validation record §3):

- §3.2 Measure-first journey (measure selector; analytical/choropleth map)
- §3.3 County name search
- §3.6 Change the active measure without restarting the journey
- §3.7 A dedicated "reset to neutral U.S. map" control (browser navigation
  and the "United States" breadcrumb/back links serve the practical need)
- §3.4 "selected measure emphasized on profile entry" (N/A — no measure
  feature exists)

This boundary is recorded so the baseline is never read as claiming those
features.

## 6. Open residual — CE-E07 manual browser / screen-reader / device checklist

CE-E07 delivered an execution-ready manual validation checklist
(`Documentation/CE_E07_Accessibility_Responsive_Validation.md.txt` §6):
real-browser rendering at desktop / tablet / mobile viewports, NVDA / JAWS /
VoiceOver read-throughs, physical touch-device interaction, and the
`prefers-reduced-motion` OS setting. **This environment has no browser
automation, no assistive technology, and no physical devices, so those
checks were not executed and are NOT represented as passed.**

Per the approved CE-E08 scope (investigation §8, Decision 1), the v0.2 UX
baseline (`ce-e08`) is declared on **automated acceptance + code audit**
(journey test green; CE-D01 provably unchanged; full regression green), with
the CE-E07 manual checklist carried forward as an **explicit, itemised
residual for a human validator to complete against a running build**:

- [ ] CE-E07 §6.1 keyboard pass (3 screens + drill-down)
- [ ] CE-E07 §6.2 screen-reader pass (NVDA and/or VoiceOver), incl. route-announcer behaviour
- [ ] CE-E07 §6.3 responsive pass at ~1280 / ~768 / ~375 px
- [ ] CE-E07 §6.4 touch pass on a physical device
- [ ] CE-E07 §6.5 reduced-motion pass with the OS setting enabled
- [ ] CE-E07 §6.6 colour-independence (greyscale) pass
