# 1. What changed

Established authoritative source-vintage and reproducibility metadata on the
canonical database **without changing any analytical value**, per
`Documentation/CE_E12A_Data_Vintage_Design.md.txt` and the catalogue in
`Documentation/ANALYTICAL_DATA_SOURCES.md.txt`.

## Schema

`Data/Model/schema.sql` — `source` gained two additive, nullable `TEXT` columns:

| Column | Meaning |
| --- | --- |
| `artifact_filename` | exact `Data/Processed` build-input workbook the source was loaded from |
| `content_sha256` | SHA-256 of that workbook's bytes |

No index, FK, `NOT NULL`, default, or change to any existing column.

## Data (all four `source` rows)

| Field | Value |
| --- | --- |
| `reference_period` | `HRSA Data Warehouse snapshot 2026-08-29` (was `v0.1 source period`) |
| `url` | `https://data.hrsa.gov/data/download` (was `NULL`) |
| `accessed_at` | `2026-08-29` (was `NULL`) |
| `artifact_filename` | per source — see catalogue |
| `content_sha256` | per source — SHA-256 of the build-input workbook |

`county_period.period` and `methodology.methodology_version` unchanged (`v0.1`).

## Migration

`Data/Model/migrate_v12_source_vintage.py` (new) — scoped, transactional,
`source`-only. Not a full `build_v01_database.py` rebuild (a rebuild would hit
the documented MUA/P `dimension_score` regeneration gap).

1. Idempotency guard: if `source` already carries both columns fully populated,
   no-op.
2. Refuses to run unless the database is exactly the `ce-e12a` file
   (sha-256 `0d8bb417…a2966`).
3. Requires each `Data/Processed` build-input workbook present and its bytes to
   match the SHA-256 documented in `ANALYTICAL_DATA_SOURCES.md.txt`.
4. Captures an exact fingerprint (row count + ordered-content SHA-256) of
   `observation`, `normalized_measure`, `dimension_score`, `composite_score`.
5. In one transaction: `ALTER TABLE source ADD COLUMN` ×2; `UPDATE` each of the
   four rows (asserting `rowcount == 1`); re-compute the analytical fingerprint
   and **abort unless byte-identical**; `PRAGMA foreign_key_check` clean;
   `COUNT(*) FROM source == 4`; all five vintage fields non-NULL. Commit,
   else roll back.
6. Post-commit read-only re-check of the analytical fingerprint.

Run once against `Data/Model/chia_v01.sqlite` with SQLite library **3.45.1**.

## Build / seed path

* `Data/Model/seed_v01.sql` — the four `source` inserts now carry the full real
  metadata (including literal `content_sha256`), so a fresh `build_v01_database.py`
  produces a database already holding it.
* `Data/Model/build_v01_database.py` — imports `hashlib`, defines
  `SOURCE_REFERENCE_PERIOD` / `SOURCE_URL` / `SOURCE_ACCESSED_AT` and
  `file_sha256()`, and after the source loop `UPDATE`s each row to converge on
  the vintage metadata with `content_sha256` **recomputed from the file the
  build actually read**.

## API / presentation

* `app/schemas/explorer.py` — `SourceRef` gains `artifact_filename` /
  `content_sha256` (`str | None`, described).
* `app/services/county_explorer.py` — `_load_provenance` selects and maps the
  two new columns. No other query changed.
* `frontend/src/lib/types.ts` — `SourceRef` mirrors the two new fields.
* `frontend/src/components/ProvenancePanel.tsx` — the page-level **Sources**
  disclosure now renders, per source and only when present: `Source download`
  (an external link to `url`), `Accessed` (`accessed_at`), `Source file`
  (`artifact_filename`), `SHA-256` (`content_sha256`). Doc comment updated. The
  per-dimension `DimensionProvenance` (deliberately minimal) is unchanged apart
  from already displaying the new `reference_period` value.
* `frontend/src/lib/countyCsv.ts` — `CSV_COLUMNS` gains
  `source_artifact_filename` and `source_content_sha256` (29 → 31), populated on
  `primary` rows; blank on `supporting` / `composite` rows (CE-E11 behaviour
  preserved — supporting evidence still has no per-variable source in v0.1).
* `frontend/src/styles/base.css` — `.provenance__artifact` (shares the existing
  code-token treatment) and `.provenance__link` (`word-break`).

  touched — proven by the transactional fingerprint check and
  `test_analytical_values_unchanged_since_ce_e12a`.

* No change to the State/County selector (CE-E13).
* Not pushed.
